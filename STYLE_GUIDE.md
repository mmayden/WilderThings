# Style Guide — WilderThings

Consistent formatting makes guides faster to read under stress. Follow these rules for all content.

## Content Safety — Highest Priority

**Inaccurate survival advice can kill people.** Style comes second to accuracy.

Before publishing any guide:

- Every factual claim is sourced from credible, citable references
- Safety warnings appear before instructions, never after
- Plant/mushroom ID includes dangerous look-alikes and regional scope
- Medical content includes a disclaimer that it does not replace professional care
- No claim is made with more confidence than the underlying source supports

See [CONTRIBUTING.md](CONTRIBUTING.md) for the full content safety checklist.

## Document Structure

Every guide uses this skeleton:

```markdown
---
tags:
  - category-tag
  - topic-tag
---
# Title

> One-line summary: what this covers and when to use it.

## At a Glance
- Most critical point 1
- Most critical point 2
- Most critical point 3

## [Body Sections — H2 headers]

### [Subsections — H3 headers]

## Common Mistakes

## Quick Reference

## See Also
- [Related Guide](../category/related-guide.md) — why it's related.

## Sources
```

### Required Sections

| Section | Purpose | Required? |
|---------|---------|-----------|
| Tags frontmatter | Search and tag-browse | Yes |
| Title (H1) | Clear, descriptive name | Yes |
| Blockquote summary | One-line "what and when" | Yes |
| At a Glance | 3-5 bullet critical takeaways | Yes |
| Body sections | Main content | Yes |
| Common Mistakes | What people get wrong | Yes |
| Quick Reference | Condensed lookup | Yes |
| See Also | Cross-category links | Yes (if related guides exist) |
| Sources | Citations, split into Primary and Additional reading | Yes |

### Enforced by `scripts/verify.py`

These are not style preferences — CI fails on them:

- **Every See Also entry carries an em-dash description** saying why a reader would
  follow it. A bare title makes the reader spend a page-load to find out whether the
  link was worth it.
- **Link text is never a bare filename**, and each guide is referred to by one name
  everywhere. In the single-file build there is no sidebar and no search box, so Ctrl+F
  is the whole navigation system.
- **Sources are split into two tiers.** Primary is authoritative, revised and publicly
  checkable — military field manuals for technique, WMS/TCCC/resuscitation councils for
  medicine, CDC/EPA/NOAA for the rest. Additional reading is trade books, labelled as
  not being what a claim should rest on.
- **One work, one citation.** Two checks cover this: books keyed on author plus main
  title, articles on author plus quoted title.
- **DANGER stays under 15% of labelled admonitions.** DANGER means *will* kill or
  seriously injure; WARNING means *could*. If every box is red the lethal ones stop
  working.

## Tags Frontmatter

Every guide starts with YAML frontmatter:

```yaml
---
tags:
  - category-tag        # matches the guide's category (medical, water, fire, etc.)
  - topic-tag           # specific topic within the category
  - cross-cutting-tag   # emergency, improvised, wilderness, etc.
---
```

4-7 tags per guide. The tags index is at `docs/tags.md` (auto-generated by MkDocs).

## Writing Rules

### Voice and Tone

- **Imperative mood.** "Apply pressure" not "You should apply pressure."
- **Present tense.** "The bow drill creates friction" not "will create."
- **Second person** for instructions. "Hold the knife at 20 degrees."
- **Active voice.** "Pack the wound with gauze" not "The wound should be packed."
- **No hedging.** "This works above freezing" not "This might possibly work in some conditions."
- **No padding.** No preamble, no motivational filler. Lead with the critical action.

### Clarity

- One idea per sentence.
- One procedure per numbered list item.
- Define jargon on first use: "Apply a tourniquet (a tight band that stops blood flow to a limb)."
- If a term appears often, link to the glossary after first definition.

### Measurements

Always provide both. Imperial first for North American context:

- `3 inches (7.5 cm)`
- `2 quarts (1.9 L)`
- `98.6°F (37°C)`

### Lists

**Numbered** for sequential steps (order matters):

```markdown
1. Clear the area of debris.
2. Lay a base of dry bark.
3. Build a teepee of kindling over the tinder.
```

**Bullets** for non-ordered items:

```markdown
- Birch bark
- Dried grass
- Cedar shavings
```

## Admonitions

Use MkDocs Material admonitions for all warnings, cautions, notes, and tips. **Never use raw blockquotes** (`> **WARNING:**`).

### Syntax

```markdown
!!! danger "WARNING"
    Never attempt to suck venom from a snake bite. This does not work and risks infection.

!!! warning "CAUTION"
    Test only a small amount. Wait 8 hours before eating more.

!!! note
    This technique requires dry conditions. See fire-in-wet-conditions.md for alternatives.

!!! tip
    Birch bark ignites even when damp — look for it first.
```

### Severity Levels

| Admonition | Use When | Color |
|------------|----------|-------|
| `!!! danger` | Risk of death or serious injury | Red |
| `!!! warning` | Risk of making the situation worse | Orange |
| `!!! note` | Important context that affects the procedure | Blue |
| `!!! tip` | Helpful technique or shortcut | Green |
| `!!! example` | Real-world illustration | Purple |

### Collapsible (for long warnings)

```markdown
??? danger "Full list of toxic look-alikes"
    Collapsed by default — reader expands.
```

## Content Tabs

Use for regional variations, alternative methods, or side-by-side comparisons:

```markdown
=== "Method A: Boiling"
    Bring water to a rolling boil for 1 minute.

=== "Method B: Chemical"
    Add 2 drops of household bleach per quart (liter). Wait 30 minutes.
```

## Internal Links

Relative paths from the current file's location:

```markdown
See [Shelter Principles](../shelter/shelter-principles.md) for site selection.
```

For same-category links:

```markdown
See [Spark and Lens Methods](spark-methods.md) for the ferro rod technique.
```

## Tables

Use for comparison data, identification keys, or quick-lookup. Mobile-friendly rules:

- **3-4 columns maximum** — wider tables cause horizontal scrolling on phones
- Short cell content — if a cell needs a paragraph, restructure as a list instead
- Use `---` separator rows with matching column count

```markdown
| Snake Feature | Venomous | Non-Venomous |
|---------------|----------|--------------|
| Head shape | Triangular | Rounded |
| Pupils | Vertical slits | Round |
```

## Headers

- **H1 (`#`)** — Document title only. One per file.
- **H2 (`##`)** — Major sections.
- **H3 (`###`)** — Subsections within an H2.
- **H4 (`####`)** — Rarely needed. If you need it, consider restructuring.

## See Also Section

Cross-navigation is a core feature. Every guide links to related guides across categories.

### Format

```markdown
## See Also

- [Guide Title](../category/guide-name.md) — brief description of the relationship.
- [Same-Category Guide](guide-name.md) — why this is relevant.
```

### Rules

- Place between Quick Reference and Sources
- Prioritize cross-category links (sidebar handles same-category)
- Include an em-dash (`—`) description after each link
- Target 3-8 links
- Add reciprocal links: A links to B → B links to A

## Mobile Considerations

Test all content at 375px width (standard phone).

- **Tables:** ≤4 columns. The CSS provides `overflow-x: auto` as a fallback, but prefer fitting the table to 4 cols.
- **Paragraphs:** Short preferred (2-3 sentences). Long prose wraps fine, but dense blocks are hard to scan in the field.
- **Quick Reference sections:** Scannable at a glance — the reader may be checking their phone in rain or cold.
- **Images:** Not currently used. If added, max-width is constrained by CSS.

## File Conventions

- **Encoding:** UTF-8
- **Line endings:** LF (Unix-style)
- **Max line length:** No hard wrap — let the renderer handle it
- **Trailing newline:** Yes — every file ends with a single newline
- **No trailing whitespace**
- **File location:** All content in `docs/`. Templates in `templates/` (not served).

## Spell Check

Run before every commit:

```bash
codespell docs/ --config .codespellrc --quiet-level=2
```

The `.codespellrc` file suppresses valid domain-specific words (`sting`, `HACE`, `trough`, `Augmentin`, etc.). If codespell flags a word that is correct, add it to the ignore list with a comment explaining why.
